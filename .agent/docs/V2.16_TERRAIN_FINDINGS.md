# V2.16 — Terrain findings and resolved defects

## Scope

`.agent` bundle from the canonical source repository into an isolated project:

```text

```

It distinguishes observed terrain evidence from CI coverage. It does not mark the
PR ready for merge and does not replace the remaining host-visible MCP gate.

## Real Graphify schema

The real installed Graphify build completed with two nodes and one edge. Its
`graph.json` is NetworkX node-link data with these root fields:

```text
directed
multigraph
graph
nodes
links
hyperedges
```

The original V2.16 readiness fixture assumed `nodes + edges`; terrain therefore
exposed a false `GRAPHIFY_CORRUPT` verdict after a successful real build.

The readiness adapter now accepts only explicit supported edge collections:

```text
nodes + edges
nodes + links
```

It still rejects absent collections, non-list collections, and contradictory
`edges`/`links` collections. The manifest records which edge field was bound.

## Concurrency defects exposed by the expanded matrix

The terrain-driven changes caused the cross-platform suite to exercise races that
had previously remained latent.

### Partial TENOR lock creation

A waiter could read a lock file while its owner was still writing JSON. An empty
parse result was interpreted as epoch zero, making a fresh lock appear stale.
The age calculation now falls back to the lock file `mtime`, and stale removal
still rechecks ownership before unlinking.

### Windows manifest temporary-file collision

Concurrent writers could generate the same timestamp-derived temporary name.
Manifest writes now use an exclusively created `tempfile.mkstemp()` file in the
same directory before `fsync` and atomic replacement.

### Destructive Windows PID probe

`os.kill(pid, 0)` is not a POSIX-style existence probe on Windows. TENOR now uses
read-only `OpenProcess` and `GetExitCodeProcess`, closes every handle, and treats
access denial as an existing but uninspectable owner.

### In-process finalization transaction

Concurrent finalizers could write `ready` and then observe another write between
the write and gate inspection. Manifest finalization now protects write plus
inspection with a reentrant in-process transaction lock; the TENOR file lock
remains the inter-process authority.

## Smoke fixture isolation

A smoke fixture previously survived `mcp_smoke` and was then correctly rejected
by `enforcement_redteam_smoke` as `GRAPHIFY_FIXTURE_FORBIDDEN`.

Graphify smoke fixtures now have an explicit scoped lifecycle:

1. snapshot the prior canonical Graphify output;
2. install and authorize the fixture;
3. execute exactly one smoke subprocess;
4. restore the prior output byte-for-byte, or restore absence;
5. restore the previous environment even when the smoke fails.

The validation runner applies separate scopes to `mcp_smoke` and
`enforcement_redteam_smoke`. Diagnostic logs live under `RUNNER_TEMP`, outside
the checkout, so the final Git hygiene gate remains strict.
